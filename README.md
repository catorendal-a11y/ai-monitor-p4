# AI Monitor P4

NOVA is a touchscreen desk companion that shows AI usage limits and reacts to registered token activity from the AI providers you select.

**Hardware:** GUITION JC4880P433 ESP32-P4, 4.3-inch ST7701S/GT911 display. **Firmware:** v1.12.1. UI, setup and documentation are in English.

## Start here

**Windows 10/11 x64:** download **ai-monitor-p4-v1.12.1-windows.zip** from this repository's **Releases**, extract the whole ZIP and double-click **AI-Monitor.exe**. Python and the firmware flasher are included. No development tools are needed.

1. Connect the screen with a USB data cable.
2. Choose **1 - First-time setup**, explicitly select your AI providers, then select the USB port.
3. On a new board, choose **4 - Install / update firmware**, then **1 - First installation**. Confirm the correct board/port. Skip this only on firmware v1.12.0+. Use the application update on older AI Monitor firmware.
4. Choose **2 - Start host** and close the menu. The companion keeps running invisibly.

[Step-by-step guide and troubleshooting](docs/QUICK_START.md)

**Security update v1.12.1:** update the PC host to get the security fixes. Existing v1.12.0 display firmware remains compatible and does not need reflashing. See the [security review](docs/SECURITY_REVIEW.md).

**Source ZIP / clone:** Python 3.10+ is required. On Windows, double-click **AI-Monitor.bat**; first launch sets up the local environment and opens the menu. Source ZIPs do not contain prebuilt firmware or executables. Linux/macOS: run `sh setup.sh`, then `.venv/bin/python tools/aim_control.py`. See the [developer guide](docs/DEVELOPMENT.md) for firmware builds.

The repository's Windows ZIP is a release asset generated by the release workflow. GitHub's automatic **Source code (zip)** is the source-only download. If no release has been published yet, the portable asset will not appear under Releases.

## Automatic Codex setup for new users

Choose **Codex** in First-time setup. The app locates the official CLI, offers the official OpenAI installer if it is missing, and offers the official sign-in flow when needed. Existing installations/accounts are reused. No password or OpenAI key is entered into the monitor. Declining a step keeps Codex selected so setup can be finished later through **7 - Provider integration help**. Quota is read through the official CLI account interface; token activity follows the local database under `CODEX_HOME`. No AI is preselected. [Detailed guide](docs/CODEX_SETUP.md).

## Provider setup

| Provider | Required for quota data | Required for token activity |
| --- | --- | --- |
| Codex | Sign in with Codex CLI on this computer. Setup prepares the official CLI; quota uses its account interface and existing supported credential store. | A readable local Codex token database, updated by supported Codex sessions. |
| ZCode | Optional: your Z.AI coding-plan API key, entered in setup. | A readable local ZCode token database. An API key is not used to read token counters. |

Official setup help: [Codex CLI](https://developers.openai.com/codex/cli/) and [ZCode account/API-key configuration](https://zcode.z.ai/en/docs/configuration). The official CLI owns sign-in and credential storage; the monitor respects CODEX_HOME and retains file access only as a legacy fallback when no CLI is available.

You never paste an OpenAI password or token into setup. ZCode's encrypted app login is not imported. The optional Z.AI key stays in local `tools/aim_host.json`; input is hidden. Enter preserves a saved key and `clear` removes it. `ZAI_API_KEY` in the process environment takes precedence over a saved key. The host does not load `.env` files automatically.

New installations have no AI preselected. Only chosen providers are monitored. See [provider support and setup](docs/PROVIDERS.md) for Claude Code, Gemini CLI, Copilot, Cursor, Antigravity and OpenCode, including which choices need an external bridge.

No keys are included in the public package. Configurations, logs and databases stay local and are ignored by Git. The firmware contains no cloud credentials. The companion uses internet access for quota queries; the panel connects by USB.

## Menu

| Choice | Result |
| --- | --- |
| 1. First-time setup | Choose AI providers and USB port. Configure ZCode only if selected. Existing settings are kept. |
| 2. Start host | Starts this folder's companion in the background. Closing the menu leaves it running. |
| 3. Stop host | Stops only hosts belonging to this folder. |
| 4. Install / update firmware | Checks the supplied firmware hash, asks for board/port confirmation, then flashes. First installation resets settings; application updates need the existing AI Monitor partition layout. |
| 5. Status | Shows local login availability, USB ports and readable token sources without making API calls. |
| 6. View recent log | Shows recent connection and polling messages. |
| 7. Provider integration help | Shows selected-provider requirements and optionally installs the Claude quota bridge. |

## Choose your robot and UI colors

Open **SET > APPEARANCE** on the display. Choose **NOVA** or the new hovering **ORBIT** companion, then select **Forest**, **Ocean**, **Amethyst** or **Ember**. The robot and theme apply immediately and are saved together on the display. Both robots use the same live activity states. Themes update all screens; provider logos/colors and low/critical warning colors retain their meanings.

## On the screen

- Animated NOVA with token-source tracking, elapsed activity time and working/resting states.
- Dashboard, detailed quota windows, reset countdowns and manual refresh.
- Low/critical warnings, session-local history and retained data during API errors.
- Persistent settings, brightness presets, gradual idle dimming and scheduled night brightness.
- Real provider logos, USB heartbeat/reconnect handling and provider retry backoff.

NOVA follows increases in local numeric token counters. Existing totals establish a baseline; generation may register only when a request finishes. Tracking identifies readable sources, not which provider generated the last increase. Token activity is not billing or per-token streaming. History clears when firmware restarts. Unsupported database schemas or missing login files cannot establish activity.
